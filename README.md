# Naija School Manager v3.0 — Backend

Multi-school cloud backend for school management: students, scores & report cards
(WAEC nine-point grading), fees, attendance, timetables, announcements and JWT auth
with three roles — **admin**, **teacher**, **student** — plus **owner-issued
license keys**: a school cannot register or operate without a valid key, and the
owner can revoke a key or disable a school at any time.

Stack: **FastAPI + SQLAlchemy**. SQLite by default (zero-config file DB),
PostgreSQL when `DATABASE_URL` is set.

## Quick start (local, SQLite)

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python seed.py        # creates Demo College (see demo credentials below)
uvicorn app.main:app --reload
```

API at http://127.0.0.1:8000 — interactive docs at `/docs`, health at `/health`.

## Docker Compose (API + PostgreSQL)

```bash
cd backend
SECRET_KEY=your-strong-secret docker compose up --build
```

Then seed the Postgres DB once:

```bash
docker compose exec -e DATABASE_URL=postgresql+psycopg2://schoolmgr:schoolmgr@db:5432/schoolmgr \
  api python seed.py
```

## Deploy free

### Render (Docker)
1. Push this folder to a Git repo.
2. Render Dashboard → **New → Web Service** → point at the repo.
3. Environment: **Docker**, Dockerfile path `Dockerfile` (repo root = backend/).
4. Add env vars: `DATABASE_URL` (create a free Render Postgres and copy its
   **Internal Database URL**), `SECRET_KEY` (generate a long random string).
5. Deploy. Run the seed once with Render's Shell:
   `python seed.py` (DATABASE_URL is already in the environment).

### Railway
1. **New Project → Deploy from Repo**, select the backend folder.
2. Add a **Postgres** plugin; Railway exposes it as `DATABASE_URL` automatically.
3. Add variable `SECRET_KEY` (generate one under Variables).
4. Deploy, then run `python seed.py` once from the service's shell/terminal.

### Fly.io

## How auth works

- `POST /auth/login` takes `school_code`, `username`, `password_or_pin`.
- Staff log in with **username + password**; students log in with
  **admission_no + PIN** (admin sets PINs via `POST /students/{id}/pin`).
- The JWT carries `role`, `school_id`, `school_code` — every request is scoped
  to the caller's school. Students get **403** on all staff endpoints;
  teachers get **403** on admin-only endpoints.

## Licensing (v3.0) — owner-controlled access

Every school needs an **owner-issued license key**. The model:

- Keys look like `NSM-XXXX-XXXX-XXXX` and are generated by the **superadmin
  (owner)** via `POST /superadmin/licenses` (`{count, label, max_students,
  expiry_days}`). Each key starts **unbound** and can be used **once**.
- `POST /auth/register-school` **requires** `license_key`. The server rejects
  unknown, revoked, expired, or already-used keys with
  `403 LICENSE_INVALID: <reason>`. On success the key is permanently **bound**
  to the new school.
- Every school-scoped endpoint (`require_staff` / `require_admin` /
  `require_student`) re-validates the license. If the key is revoked or
  expired, or the school is disabled, the caller gets
  `403 LICENSE_INVALID: <reason>`. `GET /license/status` reports the current
  state (usable even when invalid, so the app can show the reason).
- The owner (superadmin, seeded from `SUPERADMIN_USER`/`SUPERADMIN_PASSWORD`):
  - `POST /superadmin/login` → bearer token with role `superadmin`
  - `POST /superadmin/licenses` → generate keys (bulk)
  - `GET /superadmin/licenses` → list keys with bound school + status
  - `POST /superadmin/licenses/{key}/revoke` → instantly blocks that school
  - `POST /superadmin/licenses/{key}/unrevoke` → restores access
  - `GET /superadmin/schools` → all schools with license validity
  - `POST /superadmin/schools/{id}/disable|enable` → kill-switch per school
- Schools that predate licensing automatically receive a perpetual
  `legacy-auto` key at server startup (and via `seed.py`), so existing
  deployments keep working.
- The Android app (v3.0) shows a full-screen **Access locked** screen when the
  license is invalid, and its registration screen requires the license key.

Recommended owner workflow: school pays → you generate a key with a label
(`POST /superadmin/licenses {"count":1,"label":"Kings College"}`) → you send
the key to the school → they register in the app → the key binds to them.
Missed payment? Revoke the key or disable the school — their app locks on the
next API call.

### Report card (`GET /me/report-card`)

Returns per-subject `{subject, ca, exam, total, grade, remark, class_average}`,
`total`, `average`, `position_in_class` (standard competition ranking — ties
share a position), `grade_counts` for all nine WAEC grades, and an attendance
summary. `term`/`session` default to the school's current term/session.

Default WAEC bands: A1 75–100 Excellent · B2 70–74 Very Good · B3 65–69 Good ·
C4 60–64 Credit · C5 55–59 Credit · C6 50–54 Credit · D7 45–49 Pass ·
E8 40–44 Pass · F9 0–39 Fail. Override per school with `PATCH /schools/me`
(`grading_bands` JSON, same shape); `app/grading.py::grade_for()` implements it.

## Security notes

- Change `SECRET_KEY` before any real deployment.
- Passwords and student PINs are stored as bcrypt hashes only.
- `DELETE /students/{id}` fails with a DB integrity error if the student still
  has scores, fee records or attendance marks — clear those first. Deleting a
  school cascades its users and students (ORM-level).
